# Ресторанне меню та замовлення

Навчальний застосунок на C# / .NET 10, Avalonia UI 12.1.4, MVVM.
Реалізовано меню, замовлення, JSON, XML-звіт, фонові операції, скасування, логування та перевірки.
Код створено за допомогою ШІ; використання зафіксовано в AI_LOG.md.

## Вміст репозиторію

До кореня репозиторію потрібно завантажити **вміст** папки «Код проєкту»: `src`, `checks`, `data`, `docs`, `Restaurant.slnx`, файли Markdown, `.gitignore` та `.gitattributes`. Файл `Restaurant.slnx` має бути поруч із `README.md`, без додаткової вкладеної папки «Код проєкту».

Файли збирання (`bin`, `obj`, `artifacts`), журнали й тимчасові результати не входять до вихідного коду та виключені через `.gitignore`. При ручному завантаженні через браузер їх також потрібно пропустити. Приклади JSON/XML у `data` потрібні для демонстрації та включені до репозиторію.

Після клонування або розпакування ZIP відкрийте термінал у папці з `Restaurant.slnx` і виконайте команди запуску нижче. Залежності від файлів поза цією папкою немає; пакети NuGet відновлюються під час збирання.

## Запуск

Відкрийте Restaurant.slnx у середовищі з підтримкою .NET 10 або виконайте з кореня проєкту:

```powershell
dotnet run --project src/Restaurant.Desktop/Restaurant.Desktop.csproj --configuration Release
```

Потрібен .NET SDK 10 та доступ до NuGet при першому збиранні. Пакети зафіксовано у файлах проєктів.
Повне збирання: `dotnet build Restaurant.slnx --configuration Release`.

На початку у пам'яті є 51 демонстраційна позиція та 10 замовлень.
Автоматичного завантаження чи збереження немає: власний файл відкривайте на вкладці «Файли та звіт».
Перед закриттям незбережених даних з'являється підтвердження. Під час операції спочатку скасуйте її або дочекайтеся завершення.

## Користування

1. На вкладці «Меню» виберіть рядок або натисніть «Нова позиція». Введіть назву, категорію, додатну ціну й вихід порції та натисніть «Зберегти позицію».
2. Для комбо виберіть тип «Комбо», знижку 0–100 % і щонайменше дві позиції у списку складників. Поля знижки й складу для страви та напою не використовуються. Список можна прокручувати.
3. Пошук виконується за частиною назви, фільтр категорії — за повним найменуванням без урахування регістру. Порожній фільтр означає всі категорії. Натисніть «Застосувати».
4. На вкладці «Замовлення» задайте стіл і створіть замовлення. Виберіть позицію меню, кількість 1–50 і натисніть «Додати». Вибраний рядок можна вилучити або змінити його кількість до початку приготування.
5. Змінюйте статус послідовно: «Нове → Готується → Подано → Оплачено». Скасувати можна до подання. Видаляти можна нові й скасовані замовлення.
6. На вкладці «Файли та звіт» задайте шлях до JSON і збережіть дані. Імпорт замінює поточні дані після підтвердження. Пошкоджений файл не змінює поточних даних.
7. Сформуйте звіт за оплаченими замовленнями й експортуйте його у XML. Після зміни даних сформуйте звіт повторно.
8. Для перевірки навантаження імпортуйте data/restaurant-10000.json або натисніть кнопку генерації. Порівняння часу виконує прогрів і по п'ять вимірювань кожного режиму; показує середні T1, Tn та S = T1/Tn.

Відносні шляхи рахуються від папки запуску. Журнал Serilog: logs/restaurant-YYYYMMDD.log.
Повідомлення про помилку з'являється внизу вікна; у журналі містяться подробиці.
Під час фонової операції інші команди заблоковані; доступна кнопка скасування.

## Правила

Order володіє своїми OrderLine. Рядок незмінний: кількість змінюється через Order шляхом заміни рядка зі збереженням його ID.
Під час додавання фіксуються назва, категорія та результат CalculatePrice(). Зміни меню й знижки не перераховують уже додані позиції, навіть у новому замовленні.
Комбо має власну ціну, а виторг від нього належить категорії комбо. Знижка застосовується один раз; додаткової знижки на все замовлення немає.
Звіт враховує лише Paid. Кількість у звіті — сума порцій відповідної категорії.

JSON зберігає ID, час, статуси й історичні ціни. Історичний рядок може посилатися на видалену позицію: він має власні дані для звіту.
RestaurantService захищає стан через lock, повертає копії й перевіряє зміни до застосування. Імпорт перевіряє ревізію, щоб не затерти новіші зміни.
Файли спочатку записуються до тимчасового файлу у тій самій папці, потім замінюють цільовий файл.

## Межі реалізації

Це локальний навчальний застосунок без бази даних, авторизації, обліку залишків і фіскальних операцій.
Форма дозволяє вибирати різні складники комбо; повторення складника підтримується моделлю/JSON, але окремого редактора кількості складників немає.
Знімки даних спрощують цілісність, але потребують додаткової пам'яті. Це не оптимізований сервер обліку.
Скасування перевіряється між етапами: XML-серіалізування не переривається посеред запису, але скасований результат не замінює цільовий файл.
Для здавання курсової потрібно самостійно перевірити сценарії, опрацювати пояснювальну записку та чесно описати використання ШІ.
